# 强制执行说明（完整版）

> 本文档为 SKILL.md 中「强制执行要点」的完整展开，涵盖所有执行规则、阻塞确认点说明及反面案例。

---

## 核心执行原则

| 编号 | 原则 | 说明 |
|------|------|------|
| RULE-01 | **先定计划再动手** | 执行任何操作之前，**必须先确定功能分支并打印完整的待办步骤清单**，禁止未确定计划就直接开始执行 |
| RULE-02 | **步骤自检** | 每个步骤完成后必须对照该步骤的**完成条件**自检，有遗漏须在本步骤内补齐后再继续 |
| RULE-03 | **用户确认优先** | 本 Skill 包含多个 `<BLOCKING_CONFIRMATION>` 阻塞确认点，Agent 在遇到这些确认点时**必须暂停并等待用户明确回复** |
| RULE-04 | **功能独立性** | 两个功能的前置要求和执行流程各自独立，不可混用 |
| RULE-05 | **禁止输出思考过程** | 不得在输出中暴露"让我先..."、"我先..."、"同时..."、"考虑到..."等思考过程或决策理由，只输出最终决策结果 |
| RULE-06 | **禁止合理化跳过确认** | 禁止用"用户可能希望快速完成"、"这是一个简单场景"、"用户没说不要"等理由合理化跳过阻塞确认点 |

## 功能分支与待办清单

### 功能一：支付产品集成指引

**触发条件**：用户需要集成支付宝支付产品。

判定为功能一时，必须输出：`📋 待办清单：步骤 1.1 → 1.2 → 1.3 → 1.4 → 1.5 → 1.6`，并**严格**按此链式顺序逐步执行，禁止跳步、禁止合并。

### 功能二：集成问题排查指引

**触发条件**：用户在集成支付宝支付产品过程中遇到报错或其他问题。

判定为功能二时，必须输出：`📋 待办清单：步骤 2.1 → 2.2 或 2.3`，然后严格按照问题排查流程执行。

## 阻塞确认点说明

本 Skill 包含以下阻塞确认点，遇到时必须暂停等待用户明确回复：

| 位置 | 触发时机 | 等待内容 |
|------|----------|----------|
| 步骤 1.1 | 产品决策后 | 用户同意服务声明并确认接入特定产品 |
| 步骤 1.2 | 沙箱创建后 | 用户确认沙箱信息并同意继续 |
| 步骤 1.6 | 集成完成后 | 用户确认是否需要进行集成校验 |

**确认话术要求**：确认话术必须包含"请回复'同意'或'确认'"等显式要求。

## 反面案例（严禁行为）

> ⚠️ Agent 出现如下任何一种行为即视为违规

- 在未完整输出本 Skill 要求的**待办步骤清单**前，开始输出代码
- 因用户指令中存在"快速接入"、"快点"、"赶紧"等催促关键词而简化本 Skill 中执行流程，不再输出本 Skill 规定的完整待办步骤清单
- 跳步、合并步骤
- 进行"我认为..."、"简化起见..."等自行判断
- **绕过阻塞确认**：在 `<BLOCKING_CONFIRMATION>` 确认点，禁止以任何理由（包括"重新解释意图"、"任务优先级"、"系统提示"等）跳过等待，禁止假设用户已同意或使用"我将继续..."等单方面声明代替用户确认
- **输出思考过程**：在输出中暴露"让我先..."、"我先..."、"同时..."、"考虑到..."等思考过程或决策理由
- **合理化跳过确认**：用"用户可能希望快速完成"、"这是一个简单场景"、"用户没说不要"等理由合理化跳过阻塞确认点，实际行动仍继续执行而非等待
