# General Dev Preview

## 概述

这个 skill 用于承接主 Agent 已经决定需要处理的预览链路问题。它的职责是帮助 Agent 围绕 `${COZE_WORKSPACE_PATH}/.coze` 的 `[dev]` 入口完成规范化和实现落地；真正的预览逻辑应尽量落在项目内脚本或现有任务系统中，而不是把大段脆弱 shell 直接塞进 `.coze`。

进入预览链路后，`[dev]` 的职责划分、命令规范和修正方式由本 skill 及其 reference 负责说明；主 Agent 只负责判断项目是否需要进入预览链路，以及什么时候触发本 skill。

## 何时使用

- 主 Agent 已经按主 prompt 中《预览型项目判断逻辑》完成判断，并决定需要处理当前项目的预览链路。
- 任务涉及预览运行方式、`.coze` 的 `[dev]` 行为、预览命令、预览脚本、`5000` 端口约束或预览启动失败排查。
- 需要为项目**建立、恢复、统一、校正或验证**预览能力，而不是只盯着“修坏了的东西”。

## 何时不要使用

- 任务关注的是 `deploy` 行为，而不是预览阶段的 `dev` 行为。
- 任务是项目初始化、脚手架创建或 `coze init` 相关工作。
- 项目明确不是预览型项目，不需要常驻的预览进程。

## 当前支持范围

这个 skill 保留了按项目类型扩展的结构，但当前版本只提供一个可用 reference：

- `references/web-preview.md`

如果当前项目需要处理预览链路，但又不匹配现有 reference 能力，则应明确说明当前版本暂不处理，而不是在 `SKILL.md` 中临时发明一套新实现。

## 工作流

### 1. 接管前提确认

先确认以下前提：

- 主 Agent 已经完成项目级预览判断（包括查询《预览能力注册表》），并决定当前任务需要处理预览链路
- 当前任务的范围是预览阶段的 `[dev]` 链路，而不是 `deploy` 或项目初始化
- 当前需要明确的三个路径已经清楚：`${COZE_WORKSPACE_PATH}` 对应的工作区根目录、真实承载源码和运行配置的技术项目根目录、以及子项目 `.coze` 的位置（若技术项目与工作区根目录重合，则子项目 `.coze` 就是根 `.coze` 本身）

这一步的目标，是确认 skill 的输入已经成立，避免在 skill 内重新承担项目级判断职责。

### 2. 工作区入口校验

接管之后，先检查 `${COZE_WORKSPACE_PATH}/.coze`（根 `.coze`）：

- 它是否存在且合法
- 它是否与真实项目结构一致
- 它的 `[preview].preview_enable` 是否已经与主 Agent 的判断结果对齐

若技术项目位于子目录，还需确认子项目 `.coze` 是否已存在。

根 `.coze` 与子项目 `.coze` 之间的字段级一致性校验（`project_type` 等）由主 prompt 交付检查清单统一兜底，本 skill 不重复承担。

### 3. 加载适用指引

入口校验完成后，再加载当前版本可用的 reference。

当前版本只提供：

- `references/web-preview.md`

如果当前项目需要处理预览链路，但不匹配现有 reference 范围，则应在这里停止扩展，明确说明当前版本暂不支持。

### 4. 按指引处理预览链路

进入适用 reference 后，再按该指引处理预览链路。处理时遵循两个统一原则：

- 优先复用现有命令、脚本和任务系统；只有在现有能力不满足要求时，才建立最小必要的预览实现
- 让工作区根目录 `.coze` 保持薄封装，只负责调用稳定入口；真实预览逻辑尽量落在项目内脚本或现有任务系统中

如果真实源码位于子目录中，应通过根目录脚本或稳定命令进入子目录执行真实预览逻辑。

### 5. 预览服务的生命周期

预览是常驻服务，不是一次性测试。启动后的预览进程必须保持运行，agent 不得以任何方式终止它。验证（`curl` + `ss`）在服务启动后直接进行，不需要额外的测试流程。

### 6. 回流与沉淀

预览链路处理完成后，控制权回到主 Agent。此时至少要完成以下沉淀：

- 如有必要，补建项目级 `AGENTS.md`
- 更新 `AGENTS.md`，记录本次预览链路处理的前提、最终采用的预览入口、根 `.coze` 与子项目 `.coze` 的映射关系、以及长期注意事项

## 指引分流

- Web 预览场景请读取 [references/web-preview.md](references/web-preview.md)。

## 产出要求

- 预览链路处理的完成标准是**预览服务在 5000 端口实际存活**。必须实际执行 `[dev].build` 和 `[dev].run`，并通过运行时验证确认服务存活。
- `${COZE_WORKSPACE_PATH}/.coze`（根 `.coze`）最终应具备合法的 `[dev] build` 与 `[dev] run`，并且与真实预览实现一致。
- 根 `.coze` 的 `[preview].preview_enable` 应保持为 `”enabled”`。
- 若技术项目位于子目录，子项目 `.coze` 也应具备合法的 `[dev]` 和 `[preview]`。
- `[dev]` 的具体职责分离、命令规范、脚本要求和验证方式由适用的 reference 定义。
- 项目内脚本或复用的现有命令应保持清晰、可读、最小必要。
- 若源码位于子目录中，也必须保证平台最终读取的是根 `.coze`。
- `AGENTS.md` 需要记录本次预览链路处理的前提、最终采用的预览入口、根 `.coze` 与子项目 `.coze` 的映射关系、以及值得长期沉淀的栈相关注意事项；如果项目原本不存在 `AGENTS.md`，则这些内容应成为首次补建时的核心组成部分。
- 根 `.coze` 与子项目 `.coze` 之间的字段级一致性（`project_type`、`[subprojects]` 注册）由主 prompt 交付检查清单统一校验。
