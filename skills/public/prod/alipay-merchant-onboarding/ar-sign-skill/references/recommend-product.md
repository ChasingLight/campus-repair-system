# 产品推荐子 Skill

> 根据用户的业务描述，智能推荐最适合的签约产品，并说明推荐理由；如果没有匹配到合适产品，要礼貌告知当前暂无合适产品。

## ⛔ 核心原则

**一个入口：只询问用户”请简单描述一下您的业务内容”，基于描述智能推荐。**

```
✅ 必须：只询问一句”请简单描述一下您的业务内容”
✅ 必须：根据用户描述和上下文信息智能分析场景，自动推荐最适合的产品
✅ 必须：推荐结果出来后展示产品信息
✅ 必须：推荐其他产品（非当前可办理）时明确说明”该产品可推荐，但当前暂不可办理”

❌ 禁止：追问多个问题（如经营场景、技术能力、支付方式偏好等）
❌ 禁止：在推荐前向用户展示”我们支持哪些产品”
❌ 禁止：主动询问”您想签约哪个产品”（应先推荐）
❌ 禁止：将内部产品限制列表暴露给用户
```

## 1. 子 Skill 元信息

- **name**: recommend-product
- **description**: 基于用户业务描述智能推荐合适的支付宝收款/支付产品
- **触发条件**: 用户描述业务场景

## 2. 目标与职责

本子 Skill 只负责”推荐产品”，不直接进入签约资料收集。

职责包括：

1. 根据用户业务描述自动识别场景
2. 基于产品知识智能匹配最适合的产品
3. 输出推荐结果和推荐理由
4. 若命中当前主签约链路可承接的产品，输出对应 `salesCodes`

## 3. 输入信息

**只需用户提供：业务内容描述**

| 信息项 | 必填 | 说明 |
|---|---|---|
| 业务描述 | 是 | 用户简单描述自己的业务内容，如”我有一个电商网站”、”我做AI智能体服务”等 |

**从业务描述中自动提取以下信息用于匹配：**

| 提取维度 | 示例关键词 |
|---|---|
| 终端形态 | PC网站、手机网站、APP、小程序、自助设备、AI智能体 |
| 业务类型 | 电商、内容付费、会员续费、押金租赁、API服务 |
| 典型场景关键词 | 官网、网页、小程序、APP、智能体、机器人、API调用 |

### 3.1 场景匹配规则

根据用户描述和上下文信息中的关键词自动匹配产品：

| 用户描述关键词 | 匹配产品 |
|---|---|
| PC网站、电脑网页、官网、网页支付 | 电脑网站支付 |
| AI智能体、智能体、机器人调用、API付费、机器支付 | 智能收 |
| 手机网站、H5页面、移动端网页 | 手机网站支付（暂不可办理） |
| APP内支付、自有APP | APP支付（暂不可办理） |
| 小程序内支付 | JSAPI支付（暂不可办理） |
| 线下门店、收银台、面对面收款 | 当面付（暂不可办理） |
| 路边摊、小店铺、无开发能力 | 经营码（暂不可办理） |
| 会员续费、自动扣款 | 商家扣款（暂不可办理） |
| 押金、先冻结后结算 | 预授权支付（暂不可办理） |

### 3.2 信息不足处理

- 如果描述模糊无法判断，**不再追问**，直接给出最可能的推荐
- 如果完全无法判断，推荐默认产品并说明理由

## 4. 推荐流程

### 第一步：解析业务描述

从用户描述中识别关键词：

- 终端形态：PC网站、手机网页、APP、小程序、智能体等
- 业务类型：电商、内容付费、API服务、会员等
- 支付场景：网页跳转支付、机器调用付费等

### 第二步：智能匹配产品

根据识别的场景匹配最适合的产品：

| 识别场景 | 首推产品 | 推荐理由 |
|---|---|---|
| PC网站/官网/电脑网页支付 | 电脑网站支付 | 适配 PC 网页支付链路 |
| AI智能体/API付费/机器支付 | 智能收 | 适用于智能体对机器支付 |
| 手机网页/H5支付 | 手机网站支付 | （暂不可办理） |
| APP内支付 | APP支付 | （暂不可办理） |
| 小程序内支付 | JSAPI支付 | （暂不可办理） |
| 线下门店收款 | 当面付/经营码 | （暂不可办理） |
| 会员自动续费 | 商家扣款 | （暂不可办理） |
| 押金/预授权 | 预授权支付 | （暂不可办理） |

### 第三步：输出推荐结果

推荐回复必须包含：

1. 推荐产品名称
2. 推荐理由（一句话说明为什么适合）
3. 是否需要开发
4. 如命中当前可承接产品，输出 `salesCodes`

如果没有匹配到产品：

1. 说明当前暂无合适产品
2. 如判断可能是其他产品场景，建议用户前往 b.alipay.com-产品中心办理

## 5. 产品知识库

### 5.1 线下收款产品

| 产品名称 | 产品码 | 定义 | 典型场景 | 是否需要开发 |
|---|---|---|---|---|
| 当面付 | FACE_TO_FACE_PAYMENT | 商家识别用户付款介质完成收款 | 收银台、便利店、餐厅、医院窗口等线下面对面收银 | 是 |
| 订单码支付 | QR_CODE_OFFLINE | 商家生成含金额的动态二维码，用户扫码付款 | 自助售货机、自助点餐机、PC 页面订单二维码、自助设备 | 是 |
| 经营码 | MERCHANT_QRCODE_PAY | 商家展示固定收款二维码，用户扫码并输入金额付款 | 路边摊、小店铺、小微商户、无需开发的线下收款 | 否 |

#### 线下产品差异

| 对比项 | 当面付 | 订单码支付 | 经营码 |
|---|---|---|---|
| 谁扫谁 | 商家扫用户 | 用户扫商家 | 用户扫商家 |
| 二维码类型 | 接口或机具能力 | 动态二维码，金额已带出 | 固定二维码，用户手输金额 |
| 主要适用 | 线下高频面对面收银 | 订单化收款、自助设备、动态金额场景 | 小微线下、免研发收款 |
| 是否需要开发 | 是 | 是 | 否 |

### 5.2 线上收款产品

| 产品名称 | 产品码 | 定义 | 典型场景 | 是否需要开发 |
|---|---|---|---|---|
| 电脑网站支付 | FAST_INSTANT_TRADE_PAY | 用户在 PC 网页发起支付，跳转支付宝完成付款 | PC 官网、电商网站、在线教育、政务缴费网站 | 是 |
| 手机网站支付 | QUICK_WAP_WAY | 用户在手机 H5 页面发起支付，跳转支付宝 APP 或网页完成付款 | 移动端 H5、手机网页收款 | 是 |
| APP 支付 | QUICK_MSECURITY_PAY | 商家在自有 APP 内集成支付宝 SDK 完成付款 | 自有 APP 的订单支付 | 是 |
| JSAPI 支付 | JSAPI_PAY | 用户在支付宝小程序内完成支付 | 支付宝小程序内下单支付 | 是 |

### 5.3 特殊能力产品

| 产品名称 | 产品码 | 定义 | 典型场景 | 是否需要开发 |
|---|---|---|---|---|
| 智能收 | ACT_PAY | 面向 AI 智能体的机器支付收款产品 | API、数字内容、算力资源、智能体按调用付费 | 是 |
| 商家扣款 | GENERAL_WITHHOLDING | 用户先签约授权，商家后续按协议主动扣款 | 会员续费、周期缴费、自动续费 | 是 |
| 预授权支付 | PREAUTH_PAY | 先冻结资金，再按实际消费结算 | 酒店押金、租赁押金、设备押金、先享后付 | 是 |

## 6. 典型推荐规则

| 用户场景 | 首推产品 | 推荐理由 |
|---|---|---|
| 线下门店收银台，商家扫用户付款码 | 当面付 | 面对面收银效率高，适合标准收银场景 |
| 路边摊、小店铺、无开发能力 | 经营码 | 下载或打印即可用，免研发、上手快 |
| PC 官网或电脑网页收款 | 电脑网站支付 | 适配 PC 网页支付链路 |
| 手机 H5 页面收款 | 手机网站支付 | 适配移动网页支付链路 |
| 商家自有 APP 内支付 | APP 支付 | 支持 SDK 集成，用户体验更完整 |
| 支付宝小程序内支付 | JSAPI 支付 | 与小程序场景天然匹配 |
| 自助设备或动态二维码场景 | 订单码支付 | 可生成含金额的动态二维码 |
| 周期性收费、会员自动续费 | 商家扣款 | 支持签约授权后自动扣款 |
| 押金冻结、先冻结后结算 | 预授权支付 | 适合押金和预付款场景 |
| AI 智能体按调用访问资源并付费 | 智能收 | 适用于智能体对机器支付 |

## 7. 不推荐规则

以下场景不要硬推产品：

- 用户主体或业务形态明确不满足产品条件
- 用户场景与产品支付链路明显不匹配
- 用户没有线下经营场所，却想用线下码产品解决纯线上支付
- 用户没有开发能力，且当前场景又无法使用免研发产品
- 用户需求超出当前知识范围，无法做出负责任的推荐

## 8. V1 承接边界

本推荐子 Skill 可以推荐多个产品，但要区分“可推荐”和“当前签约主流程可继续办理”。

### 8.1 当前签约主流程可承接的产品

| 产品名称   | salesCode            | 说明            |
| ------ | -------------------- | ------------- |
| 智能收    | I1080300001000160457 | 当前 V1 主签约链路支持 |
| 电脑网站支付 | I1080300001000041203 | 当前 V1 主签约链路支持 |

### 8.2 输出规则

- 如果首推产品是 `电脑网站支付`，输出对应 `salesCodes`
- 如果首推产品是 `智能收`，输出对应 `salesCodes`
- 如果首推产品是其他产品，要明确说明“该产品可推荐，但当前 V1 主签约链路暂未承接”

## 9. 回复原则

- **⛔ 只询问一句"请简单描述一下您的业务内容"，不追问其他信息**
- **⛔ 不主动暴露产品列表：先推荐后展示，不在推荐前告知"我们支持哪些产品"**
- 根据用户描述和上下文信息直接推荐，不再追问补充信息
- 推荐理由必须贴合用户场景，不能只重复产品定义
- 明确告知是否需要开发，避免误导用户
- 有限制条件时要诚实说明，不夸大产品能力
- 未匹配到产品时，保持礼貌，不强推不适配产品
- 推荐结果为非当前可办理产品时，明确说明"该产品可推荐，当前暂不支持办理，请前往b.alipay.com-产品中心办理"
