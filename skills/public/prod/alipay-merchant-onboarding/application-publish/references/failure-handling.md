# Failure Handling

本文件只定义失败、恢复和超时收口。

## 1. 失败与重试原则

- 查询 / 轮询步骤允许有限重试
- 高风险写步骤不盲重放
- 设钥失败、超时或状态不明：重新发起设钥
- 意图不明确时先问；tool 报错时把错误返回给用户

## 2. 失败分类

- CLI/环境问题
- MCP 调用问题
- 业务流程问题

## 3. 恢复规则

- 支持按 `appId` 自动恢复
- 也支持按显式阶段恢复
- 恢复判断优先用 `queryApplicationInfo`，必要时补 `queryApplicationDetail`

阶段 -> 恢复动作的最小对照：

| 阶段 | 恢复动作 |
| --- | --- |
| 查询已有应用 | 查询失败就让用户重试 |
| 创建应用 | 重新判断是否已创建 |
| 设置应用公钥 | 重新发起设钥 |
| 提交应用审核 | 先短轮询；未收敛时提示去 O 站查看 |

## 4. 查询已有应用失败

- `queryApplicationList` 失败时：直接收口为“应用查询失败，请重试”
- 不继续创建、设钥或提审

## 5. 提审后超时处理

- 提审成功后短轮询约 `30 秒`
- 未收敛但已提交成功：提示去 O 站查看

## 6. 复用已有应用

- 只有 `ON_LINE` 状态应用可以复用
- 用户指定 `appId` 要复用时，必须先查状态；非 `ON_LINE` 直接拒绝复用
- 复用后只导出 `RSA2.alipayPublicKey` 到本地文件
- 写入完成后终止当前发布流程
- 查询已有应用时只列出 `ON_LINE` 应用；无可列应用时直接新建应用

## 7. diagnose 建议

- 认证：`alipay-cli diagnose auth --json`
- 网络：`alipay-cli diagnose network --json`
- 配置：`alipay-cli diagnose config --json`

## 8. 失败提示风格

失败提示固定包含：
- 失败阶段
- 原因摘要
- 下一步建议

有多种路径时，把选择权交还给用户。
