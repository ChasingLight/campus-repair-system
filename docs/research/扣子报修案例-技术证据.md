## 7. REA 可以补强什么

本次对生成产物进行源码核对，对扣子平台进行行为观察，属于广义的架构逆向研究。

REA 提供给现有 Agent 的 MCP/CLI 工具，支持网页、网络记录、JavaScript 等分析。网页研究不要求原生反编译器；实际运行还需安装、注册和浏览器连接。

| 可以补充的调查 | 可用能力 | 证据边界 |
| --- | --- | --- |
| 页面与事件关联 | browser observation、场景采集。 | 仅覆盖实际观察窗口和已保留字段。 |
| 会话与发布协议 | 离线分析 HAR/SAZ 中已保留的请求和响应。 | 未保存的响应体或流事件仍未知。 |
| 前端模块与接口 | 导出收到的脚本，追踪路由、模块与端点候选。 | 前端代码与候选关系不代表服务端代码或分支实际执行。 |
| 版本差异 | 对照截图、页面、网络和脚本。 | 缺失或截断不能当作“没有该行为”。 |
| 假设与未知项 | investigate_feature、audit_residual_unknowns 等调查提示。 | 指导调查，不会提取扣子隐藏提示词或替代编程 Agent。 |

下一步若确有协议证据缺口，限定一个项目和一次观察窗口，关联 UI 操作、会话/任务 ID、版本和事件；采集前明确需要保留的字段，输出脱敏结构。

普通 HAR 与网页网络观察不保证完整保存 SSE 业务流。需要核对实际保存内容、时间范围和遗漏标记，不能默认“拿到 HAR 即拿到全部 Agent 轨迹”。

后续已按用户要求实际运行 REA CLI，完成选定 HAR 的离线解析及两份 JS 的静态分析。新增事实、工具执行状态和取证边界统一记录于 [REA 报告](扣子编程-REA取证报告.md)；原始敏感记录保存在本机临时目录。
